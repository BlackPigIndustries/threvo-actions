# 0.6.1 release record

0.6.1 corrects the recovery, worker, and local-KEK boundaries introduced in
0.6.0. It adds no connector, action group, lifecycle state, or database
migration.

## Migration from 0.6.0

1. Pin the corrective patch:

   ```bash
   uv add "threvo-actions==0.6.1"
   ```

2. Gradual-reveal recipes that support operator recovery set
   `ActionComponents(recovery_authorization=...)`. Omission remains fail closed.
3. Recovery authorization now runs before terminal-state and revision-conflict
   returns. A caller denied by `can_recover` receives no proposal status,
   revision, preview, or safe result.
4. Recovery schedules interpret `next_attempt_at=None` with an attention reason
   as suspended operator work. A false acknowledgement produces
   `RecoveryWorkerDisposition.LEASE_LOST`.
5. Local wrapped-key stores in caller-owned PostgreSQL transactions should use
   a savepoint for `put()`. A store that proves rollback may raise
   `LocalWrappedKeyWriteRejectedError`.
6. Treat a host-supplied `proposal_reference` as a durable identity. Read and
   continue an existing proposal rather than retrying `prepare()` as an
   idempotent operation.

## Compatibility

Existing action definitions, recipes without recovery, store schemas, receipts,
canonicalization, and Stripe action identities remain compatible. The new
component field, worker disposition, and local-KEK exception are additive. The
authorization-order change is deliberately fail closed.

## Qualification

Publication requires the normal complete test, type, lint, migration,
installed-wheel, signed-tag, artifact-identity, TestPyPI, and PyPI promotion
checks. Threvo remains the maintainer-owned pilot and does not establish
independent adoption or real-provider qualification.
