# 0.6.2 release record

0.6.2 corrects the period-end subscription-cancellation eligibility boundary
identified by the Threvo pilot. It adds no connector, action group, lifecycle
state, or database migration.

## Migration from 0.6.1

1. Pin the corrective patch:

   ```bash
   uv add "threvo-actions==0.6.2"
   ```

2. A supported Stripe subscription with status `trialing` may now prepare a
   cancellation schedule or withdrawal under the same period, binding,
   authority, reservation, and verification rules as an `active` subscription.
3. Hosts that intentionally forbid cancellation during a trial should enforce
   that product rule in their authorization port. Provider eligibility no
   longer imposes it for every host.

## Compatibility

Existing action identities, request and snapshot models, active-subscription
behavior, stores, migrations, receipts, and canonicalization remain unchanged.
The patch makes one previously refused provider state eligible; execution still
requires host authorization and the existing live preconditions.

## Qualification

The focused model and action tests cover active and trialing eligibility plus
all existing cancellation flows. Publication requires the normal complete test,
type, lint, migration, installed-wheel, signed-tag, artifact-identity,
TestPyPI, and PyPI promotion checks. Threvo remains the maintainer-owned pilot
and does not establish independent adoption or production qualification.
