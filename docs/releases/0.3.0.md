# `0.3.0` release record

This minor release adds governed Stripe action groups for direct-charge refunds,
period-end subscription cancellation scheduling/withdrawal, and invoice credit
notes. All groups compose the existing `ActionDefinition` and `ActionRuntime`.
They provide strict Pydantic policies and intent models, host binding and
reservation contracts, independent verification, and optional Pydantic AI recipes.

## Migration from `0.2.0`

1. Install the exact release with `uv add "threvo-actions[stripe]==0.3.0"` after
   promotion completes, and run the host's conformance tests.
2. Existing documented Stripe connector imports remain compatible. The former
   `integrations/stripe.py` is now a package. Consumers importing private module
   internals must move to documented public exports.
3. Adopt `StripeActions.refunds`, `.subscriptions` or `.credit_notes` explicitly.
   Existing hosts can continue using their connector without adopting the facade.
   The billing groups can be configured independently of refunds.
4. Supply real host authorization, tenant-scoped versioned object resolution,
   durable immutable intent storage, resource reservations, key custody and
   reconciliation scheduling. The new in-memory examples are evaluation-only.
5. Preserve pending proposals under their existing action definitions and private
   snapshot shapes. No library schema or serialized proposal/receipt migration
   is required by this release. Do not rewrite reference-app pending proposals
   to the new facade shapes without a separate host migration.
6. Shared agent instructions now use category-neutral action terminology.
   Persisted wire discriminators and existing action identities are unchanged.

Stripe remains optional. Pydantic AI remains an edge integration and cannot grant
host authority. No experimental authoring names move into the package root.
The existing gradual-reveal support window and consumer equivalence obligations
remain in effect.

## Scope

Subscription results prove scheduling or withdrawal, never immediate termination
or entitlement changes. Initial support covers active, single-item licensed
subscriptions without schedules, pending changes, collection pauses or custom
cancellation dates.

Credit notes either reduce an open invoice or credit a paid invoice customer's
balance. Stripe's preview must match the selected lines, expected total and
allocation. Customer-balance completion also requires an independently retrieved
balance transaction. Cash-refund/mixed allocations, custom lines, quantity
credits and shipping credits are outside this contract. Credit-note email is
explicitly suppressed.

Neither the facade nor the SDK provides atomic compare-and-set against external
Stripe writers. Hosts must coordinate their own writers; unknown outcomes retain
claims and reconcile rather than resubmit. Provider metadata is correlation,
not cryptographic evidence.

## Qualification and publication

Local qualification includes 77 new Stripe model/lifecycle/SDK/agent tests,
existing regressions, type/lint checks, documentation and distribution builds.
Fixtures use Stripe Python 14.4.1 with `2026-02-25.clover`. The candidate workflow
also checks installed artifacts on Python 3.11–3.13 and database-backed adapters.
The new subscription and credit-note actions have not yet been qualified against
a live Stripe sandbox. Do not infer that qualification from the earlier refund
sandbox test or from provider-shaped fixtures.

Publication requires the repository's signed candidate/promotion workflow,
artifact qualification, adoption gate, and TestPyPI/PyPI byte verification.
Independent external adoption evidence remains pending. This source release
record is not proof of publication or a passing adoption evaluation.
