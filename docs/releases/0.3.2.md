# `0.3.2` release record

This patch publishes the corrective `0.3.1` change set from a single reviewed
`main` commit. It fixes the Stripe optional-dependency boundary, exposes runtime
observability and deterministic clocks, classifies pending refunds accurately,
and reports same-proposal concurrent execution admission correctly.

The signed `v0.3.1` source tag was created at the reviewed `develop` merge while
its candidate artifacts were built from the subsequent `main` merge commit.
Although both commits have the same source tree, the release workflow requires
one exact source identity and therefore refused promotion. The immutable tag was
preserved. No `0.3.1` artifact was published to TestPyPI or PyPI.

## Migration from `0.3.0`

1. Upgrade the exact pin with `uv add "threvo-actions==0.3.2"`, or install the
   Stripe SDK transport with `uv add "threvo-actions[stripe]==0.3.2"`.
2. Follow the complete [`0.3.1` migration guidance](0.3.1.md). Version `0.3.2`
   adds no runtime behavior beyond that corrective change set.
3. No database, stored proposal, receipt, action identity, or host-data migration
   is required.

## Qualification and publication

The full local suite, strict Ruff formatting and linting, strict mypy, Bandit,
dependency audit, documentation build, source and wheel verification, and clean
installed-artifact checks gate the release candidate. CI repeats qualification
on Python 3.11 through 3.13 and across the supported optional integrations and
database adapters.

Publication uses one CI-built candidate promoted unchanged through TestPyPI and
PyPI, with signed-tag and artifact-digest verification. Independent adoption
evidence remains pending. On 2026-09-12 the repository owner explicitly
authorized the release; the one-time `v0.3.2` publication exception uses
`skip_adoption_gate=true`. All technical, provenance, signed-tag, TestPyPI and
PyPI verification gates remain mandatory.
