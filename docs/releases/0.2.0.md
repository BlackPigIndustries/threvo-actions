# `0.2.0` release record

Status: release candidate; publish only after the signed `v0.2.0` workflow
promotes the reviewed artifacts.

`0.2.0` makes the first minor-line contract correction after `0.1.4`. It keeps
durable proposal and receipt data compatible while changing Python integration
contracts where the earlier behavior could misstate persistence, visibility,
or erasure.

## Migration from `0.1.4`

- Handle Pydantic AI `prepared_not_visible` separately from
  `preparation_denied`. It means preparation committed but the current evidence
  consumer cannot read the proposal. Do not retry or expose it; use host expiry
  and reconciliation.
- Complete proposal-bound commitment and protection providers now implement
  `create_for`, `verify_for`, `protect_for`, `unprotect_for`, and their existing
  destruction methods with a strict `ProposalIdentity`. Bind both tenant and
  proposal references into provider metadata and authenticated context.
- `WrappedDataKeyStore` now provides atomic `delete_if_matches` and returns
  `deleted`, authoritative `already_absent`, or `mismatch`. Do not implement
  erasure as a preceding read followed by an unconditional delete.
- Durable action and wrapped-key stores provide authoritative read-after-write
  visibility so acknowledgement-lost writes can be reconciled.
- Pydantic AI bindings may receive an `ActionToolFailureHandler`. Models see
  only `binding_unavailable` or `operation_outcome_unknown`; original trusted
  diagnostics remain host-controlled.

The AWS KMS extra is new in this line and had no packaged `0.1.4` API to
preserve. Re-run provider conformance, tenant-collision, ambiguous-write,
conditional-delete, and model-boundary leakage tests before promotion.
