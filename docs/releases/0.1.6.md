# `0.1.6` release record

Status: release candidate; publish only after the signed `v0.1.6` workflow
promotes the reviewed artifacts.

`0.1.6` is a packaging-compatibility release. It changes no runtime behavior,
no durable proposal or receipt data, and no Python integration contract. The
only shipped change is the `pydantic-ai` extra's dependency range, plus a
regression test that pins an existing guarantee.

`0.1.5` pinned the extra to `pydantic-ai-slim==2.33.0`. Any host that had moved
to a newer Pydantic AI could therefore not install
`threvo-actions[pydantic-ai]` at all, because an exact pin cannot co-exist with
a newer resolved version. The extra now floors the dependency at
`>=2.33.0,<3`, so the host chooses its own Pydantic AI inside the supported
major line and the extra installs alongside it. The development lock moves to
2.40.0, which is the version this release was tested against.

## Migration from `0.1.5`

- No source changes are required. Re-pin the exact patch release and reinstall.
- Hosts that pinned `pydantic-ai-slim==2.33.0` only to satisfy this extra may
  now choose any `>=2.33.0,<3` version. The extra no longer constrains that
  choice beyond the major boundary.
- The floor is not a compatibility claim for every version in the range. This
  release was exercised against 2.33.0 and 2.40.0. Run the Pydantic AI
  conformance and model-boundary tests against the version you pin.
- A `3.x` Pydantic AI is outside the range and will not resolve. That boundary
  is deliberate and moves only in a release that has been tested against it.

## Verification

The added regression proves that a deferred result filed under the `calls`
category cannot settle a financial-action approval, the class of confusion
described in `pydantic/pydantic-ai#7626`. Our handler keys only `approvals`, so
the guarantee already held; the test stops a future refactor from removing it
silently.

Re-run the Pydantic AI binding, capability-instruction, and model-boundary
leakage tests against the pinned Pydantic AI before promotion.
