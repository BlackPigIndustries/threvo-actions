# 0.4.3 release record

This patch publishes clearer product boundaries, a code-linked guarantee index,
and an executable merchant-host example. It preserves the complete 0.4.2
Python API, lifecycle behavior, serialization and persistence contract. It adds
no connector, Stripe action group, lifecycle, authoring abstraction or database
migration.

## Migration from 0.4.2

1. Upgrade the exact pin with:

       uv add "threvo-actions==0.4.3"

2. No application code or database migration is required.
3. Re-run application equivalence tests because consequential-action consumers
   should qualify every exact patch even when the supported contract is
   unchanged.

## Published evidence and guidance

- The root README now identifies the merchant/application control problem and
  places the library relative to AP2, ACP, UCP, card-network agent programs and
  provider SDKs without claiming support for those protocols.
- The guarantees index maps runtime claims to enforcing code and executable
  proof, followed by the host and model responsibilities the library cannot
  enforce.
- The explicit non-goals and protocol watch keep draft or demand-free protocol
  work outside the runtime.
- The merchant `apply_change` example uses strict, frozen Pydantic models and
  the supported runtime to prove drift refusal, safe recovery after provisional
  absence and one-write behavior under competing proposals. A pinned script
  checks that mapping against Anthropic's public `commerce-agents` retail
  fixture.
- External-authority and framework-access documents remain trigger-bound
  designs. They are not new package surfaces.

The repository owner selected Threvo as the first maintainer-owned Stripe
application test bed and ended the external-project outreach path. That work is
a separate application integration. It does not count as independent adoption
or satisfy the stabilization gate.

## Stabilization and release authorization

The 0.4 feature-release hold remains active. This patch corrects material
discoverability and adoption guidance and ships a source-distribution example;
it does not expand the supported runtime contract.

The repository owner explicitly directed publication of this exact 0.4.3
release on 13 September 2026. The release workflow's default-off exception is
bound to `v0.4.3`; it cannot authorize a later release and does not bypass
candidate qualification, signed-tag verification, artifact identity,
TestPyPI/PyPI verification or protected release environments.

## Qualification

The candidate must pass Ruff, formatting, strict mypy, the full test suite,
Bandit, dependency audit, strict documentation build, build verification, and
wheel/source-distribution checks on Python 3.11 through 3.13. PostgreSQL and
MySQL matrix checks, Stripe integrations, Pydantic AI compatibility and the
merchant fixture probe remain mandatory CI evidence.
